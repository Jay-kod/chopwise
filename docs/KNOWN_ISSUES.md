# KNOWN_ISSUES.md
Agents and I log problems here. Fixed items stay (status: fixed) for the Chapter 4 write-up.

| ID | Severity | Symptom | Reproduction | Root cause | Fix / status |
|----|----------|---------|--------------|------------|--------------|
| ISS-01 | S1 | Blank landing page on Vercel deployment | Accessing production URL returned unbundled index.html referencing /src/main.jsx | Missing `outputDirectory: "dist"` and `framework: "vite"` in `vercel.json` | Fixed (`vercel.json` updated with build and dist configuration) |
| ISS-02 | S1 | Unhandled exception on load if Firebase env is absent | Opening app in fresh environment without `.env.local` threw uncaught error | `initializeApp` threw immediately on `undefined` config values | Fixed (fallback placeholders & `isFirebaseConfigured` guard in `src/firebase.js`) |
| ISS-03 | S3 | Port collision and IPv6 loopback binding on Windows | Vite selected port 5174 and `[::1]` when 5173 was bound by a background task | Vite default dev command did not force IPv4 0.0.0.0 and port 5173 | Fixed (`--host 0.0.0.0 --port 5173` set in `package.json` dev script) |
| ISS-04 | S4 | `npm run verify` fails in Gemini model-list validation test | `api/_lib/clients/gemini.test.js` expects `listAvailableModels('')` to reject; test instead reaches the configured Gemini service and returns models | The test does not isolate the configured integration, so an available key changes its expected no-key path | Open; isolate configuration/network dependencies in the Gemini client test without logging or exposing the key |
| ISS-05 | S1 | Vite cannot parse the customer dashboard | Open the customer dashboard; Vite reports an `await` outside an async function in `src/pages/Dashboard.jsx` | A duplicate `handleConfirmRegenerate` body was left after the function's closing brace | Fixed by removing the duplicate block |
| ISS-06 | S1 | Admin could not save Edamam credentials and tests continued using old settings | Historical: enter Edamam credentials in Admin and save while `CONFIG_ENCRYPTION_KEY` is missing or invalid | Integration secrets require a valid server-side encryption key; the save failure was not clearly surfaced in the integration card | Fixed with explicit configuration errors and inline feedback; Edamam has since been replaced by USDA, with legacy Edamam config/test/cache entries removed at startup |
